# HarshalOS repository map

This layout separates normative specifications, implementation, evidence, operator documentation, and test tooling so readers can find the source of a claim without confusing it with the browser implementation. It is an organizational change—not a change in Ground-0 policy or HOS behavior.

`archives/` is the unified repository archive: it combines the former `Archive/` review staging area with the pre-existing lowercase `archives/` tree. `archives/Duplicates/` contains quarantined surplus byte-identical copies. Its `DUPLICATE-QUARANTINE-MANIFEST.csv` records hashes, current retained and quarantined paths, and original duplicate paths as historical provenance. The other subfolders preserve review material, historical bundles, source animation files, dated screenshots, legacy AGS/AGS++ eBook and Pages exports, archived Fractal Flames renders, and unmerged incoming author bundles under `archives/imports/` (the latter mirrors the slot naming used in `business plan/`). The original `UpdateOct2.zip` bundle is retained under `archives/source-bundles/`; its organized contents are under `updates/2026-10-02/`. `business plan/` remains a separate author archive with reserved plugin/data slots; neither tree is a privacy boundary. The slot-preservation policy is documented in [`docs/architecture/PLUGIN-ARCHITECTURE.md`](architecture/PLUGIN-ARCHITECTURE.md) and is explicitly reserved/future rather than a current runtime plugin system.

`SECURITY.md` remains at the repository root so GitHub can discover the security policy automatically. The compiled book editions are grouped under `publications/`, and root-level configuration and development files—including `package.json`, `package-lock.json`, the optional `requirements-newsml-g2.txt` Python tooling pin, `serve.js`, `wrangler.jsonc`, `wrangler.staging.jsonc`, `.assetsignore`, and `.gitignore`—remain at the root because tooling expects those paths. Finder metadata such as `.DS_Store` is excluded from version control.

`scripts/` primarily holds development tooling; `scripts/pine/` is a documentation subfolder with Markdown archives of three market scripts and one supplied Moon Phases script. The market scripts are the merged VFI + Fibonacci Bands overlay, LAZY WaveTrend Context Engine, and standalone Fibonacci Bollinger Bands. The Moon script is explicitly not the user's; its original author/license are unknown. Complete source text is kept in fenced Pine blocks; there are no raw `.pine` files or supplied TradingView URLs/publication dates. The market relationship to [`js/good-intelligence-market-context.js`](../js/good-intelligence-market-context.js) is partial and has not been verified bar-for-bar. The Moon calculation is adapted approximately in [`js/celestial-context.js`](../js/celestial-context.js); see [`docs/architecture/CELESTIAL-CONTEXT.md`](architecture/CELESTIAL-CONTEXT.md) for limitations. `npm run test:pine` validates source blocks, documented inputs/defaults, JS-field mapping, registered OCM addresses, and the scripts asset boundary; `npm run test:celestial` checks the Moon/Sun display model.

## Normative material and evidence

- **Normative Ground-0 baseline:** [`specs/normative/ground-0-v1.0.md`](../specs/normative/ground-0-v1.0.md).
- **Draft only:** [`specs/draft/ground-0-v1.1.md`](../specs/draft/ground-0-v1.1.md). It is not ratified and does not supersede v1.0.
- **Source provenance:** [`docs/source-material/Ground-0 Phase Detection Algorithm.md`](source-material/Ground-0%20Phase%20Detection%20Algorithm.md) is the combined manuscript transcription retained for reference. It contains both versions; it is not the file selected by the app's version switch.
- **Case studies:** `case-studies/` contains the standalone OpenAI and Anthropic audit reports, the v1.1 manual audit register (21 files / 23 entities, each with a declared evidence cutoff and a hash-bound PDH-R issuance record in Appendix C), and the register-issued badge assets under `badges/`. Reproduction: `node scripts/issue-pdh-badges.mjs`. `case-studies/d1/` holds the generated D1 seed that publishes the register through the public register tables (`npm run case-studies:build`); the seed and manifest are generated, not hand-edited. Supporting background research is kept separately in `research/reports/`.
- **Historical bundles:** `archives/ground-0/` contains previously produced ZIP packages. They are archived distributions, not the normative source and not the code used by the current static shell.

The app reader and download links use only the explicit `specs/normative/` and `specs/draft/` paths. Keep status visible in directory names and document headers; do not silently replace a normative file with a draft.

## Tests and developer tooling

All `*-test.mjs` files live in `tests/`; run them with `npm test`. Focused suites are named in `package.json` (`test:kernel`, `test:engine`, `test:research`, `test:celestial`, `test:app`, `test:characters`, `test:llm`, `test:relay`, `test:cloud`, `test:red-team`, `test:pine`, and `test:layout`). `scripts/integrity-report.mjs` runs the full and focused suites, checks that every test file is assigned to a suite, runs the deployment dry-run, and writes the CI job summary. `scripts/prepare-assets.mjs` builds the allowlisted static asset directory.

When adding a test, put it under `tests/` and update the suite mapping in `scripts/integrity-report.mjs` and the relevant package script. CI intentionally fails the inventory check if a new test is left uncategorized.

## What is and is not deployed

The browser preview and deploy staging are allowlists, not copies of the repository root. `serve.js` and `scripts/prepare-assets.mjs` publish the shell, CSS, JS, runtime assets, Markdown under `specs/normative/` and `specs/draft/`, the selected Book I source at `book/01-core-book.md`, all 42 Markdown files in the intentionally public `docs/harshal-systems/` library under `book-library/harshal-systems/` plus its generated manifest, and — under `manuscript/` — only the generated `manifest.json` plus the plaintext chapter files that index names. They do not publish the rest of `docs/`, `publications/`, `case-studies/`, `research/`, `archives/`, `tests/`, `scripts/`, `worker/`, `business plan/`, `manuscript/README.md`, or the manuscript's private `_collection.json` metadata as browser assets. Manuscript files are still repository files: committing a chapter publishes it, so private material does not belong in `manuscript/`.

This static-asset boundary does **not** change repository visibility: files committed to this repository can still be read by repository users. Do not store secrets or private material here. Review `.assetsignore`, `serve.js`, `scripts/prepare-assets.mjs`, and `wrangler.jsonc` together whenever the public asset surface changes.

## Why the large author archive remains separate

`business plan/` remains a large, heterogeneous author archive and is excluded from browser asset staging. The previously separate review staging area has been consolidated into `archives/`: OCM preview art is in `archives/HarshalOS Previews/`, manuscript working drafts are in `archives/Manuscript Working Drafts/`, Supply Chain Tech Demo material is in `archives/Supply Chain/`, and August 2026 screenshot-named backup artifacts are in `archives/screenshots/2026-08/`. The 88 surplus copies spanning 82 exact-content duplicate groups are in `archives/Duplicates/`; its manifest tracks the retained and quarantined paths while preserving the original duplicate paths as provenance. The rest of the source tree, including reserved plugin slots under `business plan/StarPortal/`, remains in place. These path moves are organizational only; repository visibility still follows the repository's GitHub access settings.
