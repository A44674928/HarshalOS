# Ground-0 Automatic Audit Template — v1.1

**Purpose:** a public-evidence audit packet that an external research application can prepare as Markdown for later parsing and deterministic Ground-0 evaluation. No API key needs to be stored in or sent from the HarshalOS website; this packet does not require a browser model connection or access to private site data.

**Target specification:** Ground-0 Phase Detection Algorithm **v1.1**, the ratified normative amendment in [`specs/normative/ground-0-v1.1.md`](../specs/normative/ground-0-v1.1.md) (adopted 2026-10-14). This version has its own input schema and does not alter the v1.0 template or input contract. The machine block is an input packet, not a computed result. Every submitted audit starts `UNREVIEWED`; an AI-produced answer, citation, hash, or classification is not independent verification or certification.

---

## Instructions for the external research application

Prepare **one file per audited entity and scope**. Use public sources only. Preserve the machine block's keys, array order, marker comments, and section headings; replace values, not structure.

1. Record the entity name, identifier (if available), exact scope, audit timestamp, and context. Do not silently broaden a service, product, subsidiary, or event audit into an entity-wide finding.
2. Use only publicly accessible artifacts. For every cited item, provide its canonical URL, publication/effective date, retrieval timestamp, page/section/paragraph locator, a short exact quotation, and the specific observable claim it supports. Encode evidence dates, C2 period boundaries, and individual resolution dates as `YYYY-MM-DD` or ISO-8601 date-times with an explicit timezone; do not use unparseable prose dates in machine fields.
3. For B1–B5 and C1–C4, `true` means YES, `false` means NO, and `null` means not demonstrated from the supplied public record. `null` is never a negative finding. Do not infer an answer merely because a source was not found; disclose the bounded search and evidence gap.
4. **Evidence cutoff (required):** `input.cutoff.utc` is the explicit UTC instant (`YYYY-MM-DDTHH:mm:ss.sssZ`). `input.cutoff.uts` must be generated by the site's `HOSUTS.uDateParts()` and `HOSUTS.formatUDate()` for that exact UTC instant. Preserve `model: "HOSUTS-UDate-v1"`, `scale: 6`, the decimal-string `scaledUDate`, and the display string exactly. The engine recomputes the UTS projection and rejects a missing or mismatched value. The UTC member is the comparison instant; UTS is its HarshalOS display coordinate, **not** a trusted clock, timestamp authority, or attestation of Ground-0. UTS is approximate and device-clock-derived; the auditor declares the cutoff and must not describe it as independently trusted time. A date-only evidence date is conservatively treated as the end of its UTC day, so it cannot score against an earlier same-day cutoff.
5. Every positive B4 answer needs a defined actor, specified action, operative procedure, and a qualifying v1.1 basis. For `NO_PENALTY_EXIT`, set `binding`, `noPenalty`, and `terminatesAction` to `true` only when the cited source establishes all three: the exit binds, it carries no penalty, and it explicitly terminates the specified action. A generic ability to leave does not qualify. Record the action in `b4.action`; the source's termination must be about that same action.
6. **C2 is provenance-gated.** A C2 YES is accepted only if its evidence establishes (a) the published route and its invocation criteria, (b) the criteria actually used to invoke that route, (c) the complete bounded set of resolved outcomes in the stated period, (d) a source for every listed outcome, and (e) a complete source set with public URLs, dates, locators, and claims. Use `OUTCOME_SET` sources for the complete set and `OUTCOME` sources for individual outcomes. `numerator` and `denominator` must exactly match the listed outcomes and the engine enforces at least 50% relief. The affirmative C2 answer's own source/date must link to an entry in `c2.sources`. If the complete outcome set is not published or cannot be bounded, code C2 `false` and record the search gap rather than claiming YES.
7. For each `true` or `false` answer, `source` must be a public URL and `notes` must identify the observable claim. For `null`, do not invent a source; leave `source` and `date` empty and explain the missing evidence in `gap`.
8. Copy a PDH exactly when one is supplied. Do not invent header fields, signatures, public keys, or a valid status. A supplied key is input to local validation, not proof of identity.
9. `candidateResult` is candidate-only. A later refresh must run the selected v1.1 contract through the engine and disclose any disagreement. Never present an external AI's calculation as the site's result.
10. Do not include private material, credentials, API keys, cookies, personal data, unpublished sources, or private conversation content. Nothing in this file requires a request to HarshalOS.

The only canonical machine input is the JSON object between `G0_AUDIT_INPUT_START` and `G0_AUDIT_INPUT_END`. Narrative prose must not be used to guess a missing machine field.

## Input contract and provenance rules

- The v1.1 input schema is `harshalos-ground0-audit-input-v1.1`; the engine requires both that schema and `input.version: "1.1"`. It never infers a version from the cutoff shape. A v1.0 packet continues to use its original schema and `YYYY-MM-DD` cutoff.
- `input.answers` positions 1–5 are B1–B5; `input.constraints` positions 1–4 are C1–C4. Do not reorder or omit entries. Every item needs an explicit boolean or `null` plus its citation or evidence gap.
- A C2 `sources` item has exactly the purpose assigned by its `role`: `ROUTE`, `INVOCATION`, `OUTCOME_SET`, or `OUTCOME`. It must include a unique `id`, a safe public `url`, an eligible `date`, a human-usable `locator`, and a `claim` supported at that locator. Each referenced ID must exist; every source must be connected to the route, invocation, complete-set record, or a resolved outcome. Source presence is validated structurally; it does not prove a link is authentic or that the cited claim is true.
- `c2.outcomeSet.outcomes` contains one unique `caseId`, a `RELIEF` or `NO_RELIEF` result, an explicit resolution `date`, and one or more supporting `sourceIds` per resolved case. Every resolution date must be inside the declared period and eligible at the cutoff; every case must have one or more `OUTCOME` sources. The numeric fields must equal the counts derived from these entries; the engine does not trust user-entered ratios.
- The starter cutoff, answers, and provenance fields are deliberately blank. They are placeholders, not evidence and not a valid audit input. Do not submit an untouched template as a completed packet.
- Reserved output fields remain engine-generated. A future importer must recalculate the classification and preserve `metadata.status: "UNREVIEWED"` until the human review is complete.

## Required output fields — reserved for the refresh engine

The external application may propose values in `candidateResult`, but only the selected, versioned Ground-0 engine can generate the published result. The result remains `UNREVIEWED` until human review.

`Entity_Name` · `Entity_Identifier` · `Audit_Timestamp` · `Evidence_Cutoff` (UTC + checked UTS projection) · `PDH_Status` · `Declared_Phase` · `Detected_Phase` · `Compliance_Status` · `Confidence_Level` · `Severity_Level` · `Badge_Status` · `Finding` · `Evidence_Summary` · `Duty_Collation_Entry_ID` · `Replication_Risk` · `Temporal_Pattern` · `Transition_History`.

## Evidence review boundary

A structurally complete packet is not an independently verified audit. URLs, dates, quotations, source IDs, and UTS coordinates do not establish authenticity, completeness, correct interpretation, identity, or trusted time. The computed phase is a deterministic rules output, not a legal finding, safety certification, identity verification, or external certification. `NO`/`NOT DEMONSTRATED` is not proof that the opposite is true; report the search boundary and remaining gap.
